---
name: offline-html-quiz
description: Build or revise an interactive HTML quiz from study material; deliver a verified offline file with scored attempts and targeted review.
---

1. Read the supplied material and, for revisions, inspect the latest authorized quiz. Preserve unchanged behavior and prior files. Follow current instructions over defaults. Match the learner level and source scope; flag consequential gaps rather than inventing facts.
2. Build a diverse bank with stable question and topic IDs, unambiguous keys, plausible distractors, and short explanations. Cover recall and application; prefer distinct questions over padded variants. Verify each key against the source or authoritative subject knowledge. Shuffle answer order without changing keys.
3. Produce a standalone UTF-8 HTML file with embedded CSS and JavaScript, no network dependencies, and a visible Start button. Show one question at a time with numbered progress; use native labeled controls and visible keyboard focus. Advance only on explicit confirmation or skip. Lock committed answers, prevent duplicate submissions, and never repeat a question within an attempt. Default to one point per correct answer and zero for incorrect or skipped answers. Show points, percentage and topic breakdown after completion; follow the selected mode for explanation timing. Offer a retry of incorrect and skipped items.
4. For practice quizzes with repeat attempts, default to user-selected attempts of 5–15 questions, a large source-grounded bank, mixed and topic modes when supported, selectable layout and palette, and cross-attempt statistics. Cap topic length at available unique items and disclose the cap; if fewer than five exist, offer a clearly labeled short attempt or mixed mode. Sample without replacement and prioritize previously incorrect items over unseen or recently correct items; do not exclude the rest of the bank. Count completed attempts only. Show total attempts, aggregate accuracy, topic scores and recent results. Persist statistics and appearance locally using a quiz-specific storage key; keep consistent IDs and version the schema when retaining history. If storage fails, keep the quiz usable in memory and disclose the limitation. Do not imply cross-device sync.
5. Offer Learn and Test modes; default to Test for scored assessments. In Learn, show feedback after each committed answer and wait for explicit Next. Allow hints and worked solutions before commitment when available; mark the answer assisted as soon as either is revealed. Report assisted and independent results separately. In Test, suppress hints, solutions and correctness until completion.
6. For repeat practice, persist a deduplicated error queue by stable question ID. Add incorrect answers; remove an item only after a correct, unassisted answer in any mode. Skips and assisted successes do not clear it. Offer a separate queue practice mode and keep weighted sampling in ordinary attempts. Apply queue updates from completed attempts only.
7. Add options only when supported by the material: filter by difficulty, task type or explicitly tagged new material and show the eligible count; offer pre-quiz review and source notes; present open responses or matching with self-check criteria outside the score unless scoring is validated; offer a separate printable bank with keys; render subject notation accessibly and keep decorative themes optional. Keep preparation aids and answer keys out of the active Test interface.
8. Verify mode-specific feedback timing, assisted scoring, and queue deduplication, persistence and clearance. Verify bank uniqueness, correct answer mapping after shuffling, selection bounds, scoring for correct/incorrect/skipped answers, completion and retry, and weighted selection. Check an offline attempt at phone width and by keyboard; for persistent quizzes, reload after a completed attempt and test denied storage. State any checks not run. Preserve the canonical output and follow the current channel's generated-HTML delivery rules; do not claim delivery without confirmation.
