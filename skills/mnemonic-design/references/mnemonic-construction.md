# Mnemonic Construction and Quality Control

## Construction record
| Field | Content |
|---|---|
| Target | Canonical fact / term / item |
| Cue | Image, phrase, story, locus, peg, or code |
| Mapping | Explicit cue feature → target feature |
| Retrieval direction | Cue → target, reverse, or both |
| Exactness | Spelling, order, units, sign, exceptions |
| Confusion risk | Similar targets / alternate interpretations |
| Verification | Untested / revised / tested |

## Construction
1. Reduce target to essential meaning without removing required detail.
2. Identify arbitrary or easily confused parts.
3. Select one cue mechanism.
4. Build a concrete, distinctive association.
5. Explain mapping in one short sentence.
6. Add a discriminator if another target could trigger the cue.
7. Test without source.
8. Decode back and compare.

## Cue quality
A useful cue is specific, discriminative, recoverable, faithful, compact, and appropriate. Vividness, motion, humor, surprise, and exaggeration are optional tools, only when they improve mapping or distinctiveness.

## Interference controls
- Give similar terms contrasting images or attributes.
- Avoid reusing the same central object for unrelated targets.
- Keep mappings stable within a set.
- Do not mix numeric coding conventions.
- Preserve negation explicitly.
- Mark exceptions as exceptions.
- For sequences, ensure each transition identifies the next item.

## Exactness
For terms, include canonical spelling and accepted variants. For numbers, decode and check leading zeros, signs, decimal points, and grouping. For procedures, preserve preconditions, branches, warnings, and terminal states; pair cues with execution practice.

## Redesign triggers
Redesign if one cue retrieves multiple answers, image does not encode target, story is remembered but mapping is not, order is reversed, exception omitted, numeric decode ambiguous, or cue takes longer to reconstruct than direct recall.
